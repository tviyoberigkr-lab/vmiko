# D1 «Кошик» — схема бази даних

Версія датасету: **koshyk-1.0.0** (константа `DATASET_VERSION` у `tools/gen_koshyk.js`).
Генератор: `tools/gen_koshyk.js` · тести: `tools/test_gen.js`.

Український інтернет-магазин побутової техніки та дрібниць. Гроші — у гривнях (UAH). Діалект SQL — PostgreSQL.

## Набори

| Набір | seed | Масштаб | Клієнтів | Замовлень | Позицій | Де лежить |
|---|---|---|---|---|---|---|
| Видимий (`visible`) | 20251101 | 1.0 | 20 000 | ≈69 600 | ≈88 500 | `data/koshyk_visible.sql`, `app/data/koshyk_visible.json`; у застосунку — схема `public` |
| Прихований перевірочний (`hidden`) | 777013 | 0.3 | 6 000 | ≈21 000 | ≈26 800 | `data/koshyk_hidden.sql`, `app/data/koshyk_hidden.json`; у застосунку — схема `hidden` |

Схема (таблиці, колонки, типи) однакова; значення різні; закладені закономірності ті самі. Точні кількості рядків друкує `node tools/gen_koshyk.js`.

## Таблиці

### `customers` — клієнти

| Колонка | Тип | Опис |
|---|---|---|
| `customer_id` | integer, PK | Ідентифікатор клієнта |
| `full_name` | text | Ім'я та прізвище (вигадані) |
| `city` | text | Місто українською: «Київ», «Львів», «Івано-Франківськ»… (24 міста) |
| `registered_at` | date | Дата реєстрації (2023-09 … 2026-09) |
| `acquisition_channel` | text | Канал залучення: `organic`, `google_ads`, `instagram`, `telegram`, `referral`, `email` |

### `products` — товари

| Колонка | Тип | Опис |
|---|---|---|
| `product_id` | integer, PK | Ідентифікатор товару |
| `product_name` | text | Назва, напр. «Павербанк Baseus Pro 20000 мАг 42» |
| `category` | text | Одна з 15 категорій: «Павербанки», «Навушники», «Електрочайники», «Пилососи», «Блендери», «Кавоварки», «Смарт-годинники», «Зарядні пристрої», «Кабелі та адаптери», «Освітлення», «Праски», «Мікрохвильовки», «Фени», «Ваги», «Кухонне приладдя» |
| `brand` | text | Бренд: Xiaomi, Philips, Bosch, Tefal, Samsung, Baseus, Anker, JBL, Rowenta, Gorenje, 2E, Gelius, Vinga, Ardesto |
| `price_uah` | integer | Поточна ціна, ціле число гривень |
| `cost_uah` | integer | Собівартість, ціле число гривень |

`price_uah` і `cost_uah` навмисно **цілі** — на них працює пастка М1 день 5: `(price_uah - cost_uah) / price_uah` дає 0, правильно — `::numeric`.

### `promo_codes` — промокоди

| Колонка | Тип | Опис |
|---|---|---|
| `promo_code_id` | integer, PK | Ідентифікатор |
| `code` | text | Код, напр. `VESNA25`, `BLACK25`, `WELCOME` |
| `discount_pct` | integer | Знижка у відсотках |
| `valid_from` | date | Діє з (включно) |
| `valid_to` | date | Діє по (включно) |

### `orders` — замовлення

| Колонка | Тип | Опис |
|---|---|---|
| `order_id` | integer, PK | Номер замовлення (зростає з часом) |
| `customer_id` | integer → `customers` | Хто замовив |
| `order_date` | date | Дата замовлення (2024-01-01 … 2026-09-30) |
| `created_at` | timestamp | Точний час створення (без часового поясу, київський час) |
| `status` | text | `delivered`, `cancelled`, `returned`, `in_transit` |
| `delivery_method` | text | «Нова пошта», «Укрпошта», «Самовивіз» |
| `delivery_date` | date, NULL | Дата доставки. **NULL** для `cancelled` і `in_transit` |
| `promo_code_id` | integer → `promo_codes`, NULL | Застосований промокод |
| `discount_uah` | numeric(12,2) | Сума знижки |
| `total_uah` | numeric(12,2) | Сума до сплати = Σ(`quantity` × `unit_price_uah`) − `discount_uah` |

### `order_items` — позиції замовлень

| Колонка | Тип | Опис |
|---|---|---|
| `order_item_id` | integer, PK | Ідентифікатор позиції |
| `order_id` | integer → `orders` | Замовлення |
| `product_id` | integer → `products` | Товар |
| `quantity` | integer | Кількість (1–2) |
| `unit_price_uah` | integer | Ціна за одиницю на момент замовлення |

### `returns` — повернення

| Колонка | Тип | Опис |
|---|---|---|
| `return_id` | integer, PK | Ідентифікатор |
| `order_id` | integer → `orders` | Повернене замовлення (його `status` = `returned`) |
| `return_date` | date | Дата повернення |
| `reason` | text | Причина |
| `refund_uah` | numeric(12,2) | Повернена сума |

Зв'язки: `customers 1—N orders 1—N order_items N—1 products`; `orders N—1 promo_codes`; `orders 1—0..1 returns` (у дублікатів — теж свій рядок повернення).

## Закладені закономірності (перевіряє `tools/test_gen.js` на обох наборах)

| # | Інсайт | Як закладено | Де в треку |
|---|---|---|---|
| 1 | **Провал виручки в березні 2025** (≈0,66–0,7 від сусідніх місяців; березень — мінімум 2025 року) | Промокод `VESNA25` у березні 2025 не застосовувався: 85% таких покупців кидали кошик, решта платили без знижки (0 застосувань у березні); плюс загальний відтік −22% | М1 день 9, проєкт М1 п.4 |
| 2 | **~3% дублікатів замовлень** (подвійний клік) | Той самий `customer_id`, `total_uah`, та сама хвилина `created_at`, новий `order_id`, ті самі позиції | М2 «Дедуплікація», проєкт М2 |
| 3 | **Telegram: вищий середній чек, гірші повторні покупки** | Клієнти з `telegram` обирають дорожчі товари (чек ≈ +35%), частка повторних покупців ≈0,35 проти ≈0,78 в інших каналах | М1 день 8, проєкт М2 |
| 4 | **NULL у `delivery_date`** для скасованих (і ще не доставлених) | ≈7% рядків — пастка `COUNT(*)` vs `COUNT(delivery_date)` | М1 дні 3, 7 |
| 5 | **Пік «Павербанків» у листопаді 2025** (≈9× середнього місяця) | Вага категорії ×7 у 11.2025 (відключення світла) | М2, М7 |
| 6 | «Сироти» | ≈22% клієнтів без жодного замовлення; 8–9 товарів без продажів | М2 LEFT JOIN |
| 7 | Сезонність | Листопад–грудень вище, зима нижче | М1 день 9 |

## Як завантажити SQL у свій Postgres (необов'язково)

```
psql -d mydb -f data/koshyk_visible.sql
```

Файл створює таблиці в поточній схемі (за замовчуванням `public`) з первинними і зовнішніми ключами та індексами.
У браузері застосунок вантажить JSON через `COPY` **без зовнішніх ключів** (швидший старт; на результати запитів не впливає) — див. `docs/decisions.md`.
